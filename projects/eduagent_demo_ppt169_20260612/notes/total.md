# 01_cover

开场直接给结论：EduAgent 不是一个问答机器人，而是一个围绕学生画像、知识中枢、多 Agent 协同和学习反馈构建的智能学习系统。今天的展示重点是它如何把赛题中的个性化、多模态、多智能体和防幻觉要求落到一个可运行的工程链路中。

# 02_pain_points

高等教育不是缺资源，而是资源和学生状态之间缺少匹配机制。学生基础、目标和节奏差异很大，传统课堂和通用问答工具都很难持续理解学生，也很难把生成内容沉淀为后续可复用的学习资产。

# 03_value_chain

EduAgent 的核心价值可以概括成四步：先理解学生，再组织知识，再生成资源，再陪伴学习。每一步都有对应的工程模块，不是停留在概念层面。

# 04_architecture

系统全景里，前端负责流式交互和多模态卡片，FastAPI 提供 API 层，LangGraph 编排多个 Agent，LLM Wiki 统一提供知识图谱和 RAG 检索，底层数据和资产服务沉淀学习记录、资源和向量索引。

# 05_ai_fusion

前沿 AI 技术在这里不是简单堆叠，而是拆成可控组件。核心链路以讯飞星火为主，RAG 和课程图谱限定学术内容边界，讯飞安全护栏与 TTS 扩展安全和语音体验；视觉资产与图片型 PPT 属于辅助展示能力，不作为核心推理链路。

# 06_agents

多 Agent 的价值在于分工和可观测。Router 负责识别意图，Profile 更新画像，Planner 拆解资源任务，Doc、Quiz、Code、Media、Video 和 Tutor 分别生成不同学习支持，并记录节点耗时和状态。

# 07_wiki

LLM Wiki 是全系统的共享知识中枢。它包含静态课程图谱、向量检索、来源片段和 Wiki 条目回写。这里的图谱负责课程结构与前置关系，内容回写作用于条目和向量检索库，不改变图谱拓扑。

# 08_profile

画像设计满足赛题不少于 6 维的要求，当前实现为 8 维。它来自自然语言和学习行为，不需要学生先填长表单，并会反过来影响讲解深度、题目难度、路径节奏和资源形式。

# 09_resources

资源生成覆盖 8 类形态，但成熟度要说清楚：讲义、导图、题目、代码和拓展阅读是核心已实现能力；PPT 图片/大纲、动画脚本与动画包、B站视频推荐属于辅助或实验性能力。重点不是夸大资源数量，而是把每类资源的边界讲清楚。

# 10_loop

演示脚本围绕反向传播算法跑通学生侧闭环：登录、画像候选确认、资源生成、测验答题、错题复习、学习路径、学习活动记录和 Wiki 搜索。测验结果会在 API/Service 层写入错题、画像 knowledge_base/weak_points 和路径节点；Agent 可观测面板展示链路耗时、状态和资源生成过程。

# 11_trust_safety

可信和安全由三段防线共同承担：生成前先走 RAG 检索，生成中保留 sources、confidence 和来源片段，生成后再通过讯飞安全护栏、本地规则和离线 eval 检查风险与结构质量。

# 12_engineering

工程实现强调可运行、可观测和可回退。SSE 避免白屏等待，资源生成分层并行降低等待时间，Agent 事件记录让评委能看到内部链路。当前边界也要主动说明：PPTX 是大纲型导出，图片型 PPT 单独展示；动画导出为 HTML、字幕和可选旁白音频包，完整 MP4/WebM、OCR 与生产级对象存储是后续增强。

# 13_innovation

EduAgent 的创新点不是增加一个聊天窗口，而是把画像闭环、可信生成和工程编排组合成可验证的学习过程编排中枢。8 维画像来自自然语言抽取与规则兜底，并由测验反馈更新；RAG 混合检索配合 sources/confidence 和安全过滤控制事实边界；LangGraph 分层并行和节点事件让失败可定位、资源可复查。

# 14_close

最后总结：系统已覆盖比赛核心要求，包括 LangGraph 多智能体、8 维画像、5 类以上资源、个性化路径、智能辅导、测验与错题评估、防幻觉和流式体验。后续增强方向包括完整视频导出、OCR、更多课程知识库和生产级对象存储；答辩时主张核心闭环可演示，同时主动说清能力边界。
