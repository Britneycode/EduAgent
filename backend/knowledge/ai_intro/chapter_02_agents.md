# 第2章 智能体与问题求解

## 本章学习目标

完成本章学习后，你应该能够：

1. 解释什么是智能体，以及智能体与环境的交互关系
2. 区分四种主要类型的智能体及其适用场景
3. 使用PEAS框架描述一个智能体系统
4. 理解环境的不同特性维度及其对智能体设计的影响
5. 掌握问题形式化的基本步骤

## 核心概念

- **智能体（Agent）**：能够感知环境、做出决策并采取行动的实体。它是AI系统的基本抽象单元。
- **环境（Environment）**：智能体所处的外部世界，智能体通过传感器感知它，通过执行器作用于它。
- **感知（Perception）**：智能体通过传感器从环境中获取信息的过程。
- **行动（Action）**：智能体通过执行器对环境施加影响的过程。
- **PEAS框架**：描述智能体系统的标准方法，包括Performance（性能度量）、Environment（环境）、Actuators（执行器）、Sensors（传感器）。
- **问题形式化**：将一个实际问题抽象为可以被算法处理的形式化描述。

## 知识讲解

### 2.1 什么是智能体

智能体是AI中最基本、最重要的概念之一。简单来说，智能体就是一个能够"感知—思考—行动"的系统。

**智能体的基本循环：**

```
感知 → 内部处理（思考/推理/学习）→ 行动 → 环境变化 → 再感知 → ...
```

**为什么用"智能体"这个概念？** 因为它提供了一个统一的框架来理解所有AI系统。无论是搜索引擎、自动驾驶汽车还是聊天机器人，都可以抽象为"感知环境→做出决策→执行行动"的循环。

**关键区分：**
- 智能体 ≠ 机器人：智能体可以是纯软件的（如搜索引擎爬虫）
- 智能体 ≠ 程序：智能体具有自主性，能在没有人为干预的情况下做出决策
- 智能体可以是物理实体（机器人），也可以是虚拟存在（软件代理）

### 2.2 智能体的类型

根据内部架构和决策机制的不同，智能体可以分为以下类型：

**类型一：简单反射型智能体（Simple Reflex Agent）**

- 工作原理：直接根据当前感知做出反应，使用"如果…则…"规则
- 类比：就像膝跳反射——有刺激就有反应，不需要"思考"
- 优点：实现简单，响应速度快
- 缺点：只能处理完全可观察的环境，无法处理需要记忆或推理的情况
- 例子：恒温器——温度低于设定值就加热，高于就停止

**类型二：基于模型的反射型智能体（Model-Based Reflex Agent）**

- 工作原理：维护一个内部世界模型，追踪环境中不可直接观察的状态
- 类比：开车时你知道前车刚才在你前面（即使被遮挡看不到），因为你有一个"世界模型"
- 优点：能处理部分可观察的环境
- 缺点：世界模型可能不准确，需要持续更新
- 例子：扫地机器人——它需要记住哪些区域已经清扫过

**类型三：基于目标的智能体（Goal-Based Agent）**

- 工作原理：不仅考虑当前状态，还考虑行动是否有助于达成目标
- 类比：导航软件不仅知道你现在的位置，还会规划到达目的地的路线
- 优点：能进行前瞻性思考和规划
- 缺点：需要明确定义目标，搜索空间可能很大
- 例子：GPS导航系统、国际象棋程序

**类型四：基于效用的智能体（Utility-Based Agent）**

- 工作原理：使用效用函数量化不同结果的"好"的程度，选择使效用最大化的行动
- 类比：投资决策——不只是要"赚钱"（目标），还要考虑风险和收益的权衡（效用）
- 优点：能在多个目标之间进行权衡，处理不确定性
- 缺点：效用函数的设计可能很复杂
- 例子：投资组合优化系统、自动驾驶中的风险评估

**常见误区：** 认为更高级的智能体类型总是更好的。实际上，对于简单的控制问题，反射型智能体就足够了，使用复杂架构反而是浪费。

### 2.3 环境类型

智能体的设计必须考虑它所处环境的特性。环境可以从多个维度进行分类：

| 维度 | 说明 | 示例 |
|------|------|------|
| 完全可观察 vs 部分可观察 | 智能体能否获取环境的全部状态 | 国际象棋（完全）vs 扑克牌（部分） |
| 确定性 vs 随机性 | 下一状态是否完全由当前状态和行动决定 | 棋类游戏（确定）vs 天气预报（随机） |
| 片段式 vs 序列式 | 当前决策是否影响未来的决策 | 垃圾分类（片段）vs 下棋（序列） |
| 静态 vs 动态 | 环境在智能体决策时是否会改变 | 离线国际象棋（静态）vs 自动驾驶（动态） |
| 离散 vs 连续 | 状态和行动的数量是有限的还是无限的 | 棋类游戏（离散）vs 机器人控制（连续） |
| 单智能体 vs 多智能体 | 环境中是否有其他智能体 | 拼图（单）vs 足球比赛（多） |

**为什么重要：** 环境特性直接决定了智能体应该采用什么架构。在动态、部分可观察、多智能体的环境中（如自动驾驶），你需要远比静态、完全可观察环境（如棋类游戏）更复杂的智能体。

### 2.4 PEAS描述框架

PEAS是描述任何智能体系统的标准框架。设计AI系统的第一步就是明确其PEAS描述。

**以自动驾驶汽车为例：**

| 要素 | 描述 |
|------|------|
| **P**（Performance，性能度量） | 安全到达目的地、遵守交通规则、乘客舒适度、行驶时间 |
| **E**（Environment，环境） | 道路、其他车辆、行人、交通信号、天气条件 |
| **A**（Actuators，执行器） | 方向盘、油门、刹车、转向灯、喇叭 |
| **S**（Sensors，传感器） | 摄像头、激光雷达、GPS、超声波传感器、陀螺仪 |

**以智能垃圾邮件过滤器为例：**

| 要素 | 描述 |
|------|------|
| P | 正确分类率、误判率、用户满意度 |
| E | 收件的邮件、用户反馈 |
| A | 将邮件标记为垃圾/正常、移入垃圾箱 |
| S | 邮件内容、发件人地址、邮件头信息、用户历史行为 |

### 2.5 问题形式化

在设计智能体来解决问题之前，我们需要将实际问题"形式化"——用精确的数学或计算语言来描述它。

**问题形式化的五个关键要素：**

1. **初始状态（Initial State）**：智能体开始时的状态
2. **行动（Actions）**：在给定状态下，智能体可以执行的所有合法操作
3. **转移模型（Transition Model）**：执行一个行动后，状态如何变化
4. **目标测试（Goal Test）**：判断当前状态是否为目标状态
5. **路径代价（Path Cost）**：衡量解决方案的代价（如时间、资源）

**示例：八数码问题的形式化**

```
初始状态：3×3方格中的数字排列，如 [1,2,3,4,_,5,6,7,8]
行动：将空格与相邻数字交换（上、下、左、右）
转移模型：交换后的新排列
目标测试：排列是否为 [1,2,3,4,5,6,7,8,_]
路径代价：每一步代价为1
```

**为什么重要：** 正确的形式化是解决问题的一半。如果形式化不正确，再好的搜索算法也找不到好的解。例如，如果在路径规划中忽略了"路径代价"，智能体可能找到一条"能到达目的地但绕了地球一圈"的路径。

## 关键公式或算法流程

**智能体通用决策流程：**

```
function AGENT(percept) returns action
    state  ← UPDATE_STATE(state, percept, action)   // 更新内部状态
    action ← CHOOSE_ACTION(state, knowledge)          // 选择行动
    return action
```


## 易错点与常见误区

1. **误区：智能体必须有"身体"。** 智能体可以是纯软件的，如搜索引擎的爬虫程序、推荐系统等。"Agent"是一个抽象概念，不依赖物理形态。

2. **误区：更复杂的智能体类型总是更好。** 对于简单、完全可观察的环境，简单反射型智能体就够用了。过度设计反而增加系统复杂度和出错风险。

3. **误区：环境特性是固定的。** 同一个问题在不同抽象层次下，环境特性可能不同。例如，自动驾驶在高速公路上近似"确定性"，在城市复杂路况中则是高度"随机性"的。

4. **误区：问题形式化是"显而易见"的。** 实际上，选择什么作为状态、定义什么行动，往往决定了问题的难度。不同形式化方式可能导致搜索空间相差数个数量级。

5. **误区：把"问题求解"等同于"搜索"。** 搜索是问题求解的一种重要方法，但不是唯一的。有些问题可以用约束满足、逻辑推理或机器学习等方法解决。

## 练习题

### 选择题

**1. 一个扫地机器人需要记住哪些区域已经清扫过，这属于哪种类型的智能体？**

A. 简单反射型智能体
B. 基于模型的反射型智能体
C. 基于目标的智能体
D. 基于效用的智能体

> **答案：B**
> 解析：扫地机器人需要维护一个内部模型（已清扫区域的地图），这超越了简单反射型。它主要根据当前感知和内部记忆做出反应，属于基于模型的反射型智能体。

**2. 以下哪个环境最适合使用简单反射型智能体？**

A. 自动驾驶汽车
B. 恒温器控制系统
C. 股票交易系统
D. 医学诊断系统

> **答案：B**
> 解析：恒温器环境是完全可观察、确定性、静态的，"如果温度低于设定值则加热"这种简单规则就足够了。其他三个选项的环境都要复杂得多。

**3. PEAS中的"E"代表什么？以搜索引擎为例，"E"指的是？**

A. Evaluation（评估指标）
B. Environment（环境）
C. 互联网上的所有网页、用户的搜索请求
D. 网页排名算法

> **答案：B和C均应选，但若单选则选B。**
> 解析：PEAS中E代表Environment（环境）。对搜索引擎来说，环境包括互联网上的网页内容、用户的搜索查询、点击行为等。D是算法层面的东西，不是环境。

### 判断题

**1. 在PEAS描述中，同一个智能体的性能度量（P）在不同应用场景下应该保持一致。（ ）**

> **答案：错误**
> 解析：性能度量应该根据具体应用场景来定义。例如，同样是"翻译智能体"，用于日常对话的翻译和用于法律文件的翻译，对准确性的要求完全不同，性能度量也应不同。

**2. 如果一个环境是完全可观察的，那么基于模型的智能体就完全没有用处。（ ）**

> **答案：错误**
> 解析：即使环境完全可观察，基于模型的智能体仍然有用。例如，它可以预测环境的未来变化（如果当前状态A，执行行动X，下一状态会是什么），从而做出更好的决策。

### 简答题

**1. 使用PEAS框架描述"智能垃圾邮件过滤器"系统，并说明其环境类型。**

> **参考答案：**
> - P（性能）：邮件分类正确率、误判率（将正常邮件误判为垃圾邮件的比率）、漏判率
> - E（环境）：收件箱中的邮件、邮件内容和元数据、用户反馈（标记为垃圾/非垃圾）
> - A（执行器）：将邮件标记为垃圾邮件、移入垃圾邮件文件夹、允许邮件通过
> - S（传感器）：邮件文本内容、发件人地址、邮件头信息、附件类型、用户历史标记记录
> - 环境类型：部分可观察（无法完全判断发件人意图）、确定性（对给定邮件特征，分类结果确定）、序列式（每次分类会影响后续的过滤规则更新）、动态（垃圾邮件策略在不断变化）

**2. 将"8-皇后问题"进行问题形式化，列出五个关键要素。**

> **参考答案：**
> - 初始状态：8×8的空棋盘
> - 行动：在棋盘的某一行某一列放置一个皇后（或逐步在每一行放一个皇后）
> - 转移模型：放置皇后后，棋盘状态更新，增加新的约束
> - 目标测试：8个皇后都被放置，且没有任何两个皇后互相攻击（同行、同列、同对角线）
> - 路径代价：每放置一个皇后代价为1（或不关注代价，只关注可行性）

### 实践题

**1. 选择你日常生活中的一个AI产品（如智能音箱、推荐系统、智能翻译等），完成以下任务：（a）用PEAS框架完整描述该系统；（b）分析其环境类型（从6个维度）；（c）判断它属于哪种智能体类型，说明理由。**

> **参考思路：**

> - P：语音识别准确率、意图理解准确率、任务完成率、响应速度
> - E：用户的语音指令、家庭环境噪音、可控制的智能家居设备
> - A：语音输出（回答）、执行操作（播放音乐、控制设备）
> - S：麦克风阵列、WiFi连接
> - 环境类型：部分可观察（听不清所有背景声音）、随机性（用户意图不确定）、动态（用户随时说话）、连续（语音信号是连续的）、多智能体（可能有多个用户）
> - 智能体类型：基于模型的反射型——它维护对话上下文（内部模型），根据当前对话状态做出反应

## 代码实操建议

```python
# 实验1：实现一个简单的反射型智能体——恒温器

class ThermostatAgent:
    """简单反射型智能体：恒温器"""

    def __init__(self, target_temp=22, tolerance=2):
        self.target_temp = target_temp
        self.tolerance = tolerance

    def perceive(self, current_temp):
        """感知当前温度"""
        self.current_temp = current_temp

    def act(self):
        """根据感知做出反应"""
        if self.current_temp < self.target_temp - self.tolerance:
            return "加热"
        elif self.current_temp > self.target_temp + self.tolerance:
            return "制冷"
        else:
            return "保持"

# 模拟运行
agent = ThermostatAgent(target_temp=22, tolerance=2)
temperatures = [18, 19, 21, 23, 25, 27, 22, 20]

for temp in temperatures:
    agent.perceive(temp)
    action = agent.act()
    print(f"当前温度: {temp}°C → 行动: {action}")
```

```python
# 实验2：实现一个基于模型的智能体——简单扫地机器人

class VacuumAgent:
    """基于模型的反射型智能体：扫地机器人"""

    def __init__(self, grid_size=5):
        self.grid_size = grid_size
        self.internal_model = {}  # 内部模型：记录每个位置的状态
        self.position = (0, 0)

    def perceive(self, position, is_dirty):
        """感知当前位置和脏污状态"""
        self.position = position
        self.internal_model[position] = "dirty" if is_dirty else "clean"

    def act(self):
        """决策：清扫当前位置或移动到下一个位置"""
        if self.internal_model.get(self.position) == "dirty":
            return "清扫"
        else:
            return "移动到下一个位置"

# 使用示例
agent = VacuumAgent()
rooms = [((0,0), True), ((0,1), False), ((1,0), True), ((1,1), True)]

for pos, is_dirty in rooms:
    agent.perceive(pos, is_dirty)
    action = agent.act()
    print(f"位置: {pos}, 脏污: {is_dirty} → 行动: {action}")
```
