# 复杂度基准测试

## 1. 案例目标
用 `timeit` 实测 $O(n)$、$O(n\log n)$、$O(n^2)$ 三种典型代码的运行时间，直观理解"增长率"的含义。

## 2. 完整代码

```python
import timeit
import math

def linear(n: int) -> int:
    total = 0
    for i in range(n):
        total += i
    return total

def nlogn(n: int) -> int:
    data = list(range(n, 0, -1))  # 最坏输入
    data.sort()                   # Timsort: O(n log n)
    return data[0]

def quadratic(n: int) -> int:
    count = 0
    for i in range(n):
        for j in range(n):
            count += 1
    return count

if __name__ == "__main__":
    for n in (1_000, 2_000, 4_000):
        t_lin = timeit.timeit(lambda: linear(n), number=10) / 10
        t_nln = timeit.timeit(lambda: nlogn(n), number=10) / 10
        t_quad = timeit.timeit(lambda: quadratic(n), number=10) / 10
        print(f"n={n}: O(n)={t_lin:.4f}s  O(nlogn)={t_nln:.4f}s  O(n^2)={t_quad:.4f}s")
```

## 3. 预期输出与分析

n 翻倍时的典型观测（数值因机器而异）：

| n | O(n) | O(n log n) | O(n²) |
|---|---|---|---|
| 1000 | ~0.02s | ~0.05s | ~0.04s |
| 2000 | ~0.04s（×2） | ~0.11s（×2.2） | ~0.16s（×4） |
| 4000 | ~0.08s（×2） | ~0.24s（×2.2） | ~0.64s（×4） |

- $O(n)$：n 翻倍耗时翻倍；
- $O(n\log n)$：翻倍再多乘约 2.1 倍系数；
- $O(n^2)$：耗时 ×4。

## 4. 讨论
1. 为什么实测比例与理论不完全一致？（缓存、分支预测、解释器开销、常数因子）
2. 把 quadratic 的输入加倍到 $n=10^5$ 会怎样？据此理解"渐近分析决定算法能否扩展到大规模输入"。
