# 10 · 演示视频逐字台本（录制稿）

> 配套《03_演示视频分镜脚本》使用：镜号、时长、画面与 03 完全对齐，
> 本节只负责把「旁白/字幕」从要点升级为**可张口就念的逐字稿**。
> 总时长约 3 分钟，旁白约 600 字，语速放慢、留出生成等待的画面时间。
> 录制时照读即可，括号内为画面提示，不念出声。

---

## C1 · 片头（0:00–0:10）

画面：片名「EduAgent 个性化学习智能体」+ 赛道名 + remio logo，淡入。

旁白：
高校学习里有一个绕不开的浪费——同一份讲义、同一套题，发给基础完全不同的学生。
一台问答 AI，回答得再好，也补不上这个缺口。

---

## C2 · 痛点（0:10–0:25）

画面：左右对比，左边「千人一面」，右边「千人千面」，可配排版字幕。

旁白：
因为学生真正缺的，不是一个答案，而是一个闭环：
先懂这个人是谁，再为他规划，再生成属于他的资源，最后陪他答疑。

---

## C3 · 画像（0:25–0:45）

画面：实机输入框打字「我是计算机专业大一学生，基础一般，目标是期末不挂科，想复习 TCP 三次握手」；随后画像确认卡弹出，镜头对准卡片。

旁白：
这是 EduAgent，十个 Agent 协同的个性化学习智能体。
我只说了一句人话，它立即认出两件事：我要建档，我要复习。
第一个响应的，是画像 Agent——它串行先行，因为其他 Agent 都要靠它。

---

## C4 · 规划（0:45–1:05）

画面：学习计划 list 展开，讲义 / 练习题 / 代码 / 思维导图 / 拓展阅读，逐项高亮。

旁白：
画像一旦确定，规划 Agent 把「复习 TCP 三次握手」拆成五路并行任务：
讲义、题目、代码、导图、拓展阅读。

---

## C5 · 并行生成（1:05–1:50，重点镜头）

画面：分屏，讲义卡、选择题、代码卡、思维导图依次浮现；每张卡文末的来源行给特写。

旁白：
接下来是重点——它们并行产出。
注意每一个结果的结尾，都跟着一条来源引用，标注它来自课程知识库的哪一章、哪一节。
生成靠的是检索到的课程原文，而不是模型凭空发挥。这就是防幻觉。

---

## C6 · 苏格拉底答疑（1:50–2:20）

画面：输入「为什么是三次握手，而不是两次？」；答疑卡浮现，subtitle「📚 课程知识库」给特写。

旁白：
我再追问一个更刁钻的问题：为什么是三次，不是两次？
答疑 Agent 不直接报答案——它反问我，一步步引着我走；
而答案覆盖的是哪一层来源，明明白白标在卡片上。

---

## C7 · 自动化 + 跨产品（2:20–2:50）

画面：双屏对比，左边订阅触发薄弱点自测题推送，右边在另一个智能体客户端调用 MCP 工具。

旁白：
它还远远不止于此。
薄弱点会被自动回访，复习提醒自动触发；
同一套引擎，还能以 MCP 工具的形式，在别的智能体产品里被直接调用。

---

## C8 · 收束（2:50–3:00）

画面：10 Agent 架构图定格 + 片名 + 开源协议声明。

旁白：
一句话收尾：这十个 Agent 不是炫技。
它们让「个性化学习」，第一次变成了一个可以交付的闭环。

---
