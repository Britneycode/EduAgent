## 二、要解决的问题（赛道核心命题回应）

高校课程学习中，"千人一面"是核心痛点：同一个知识点，不同基础、不同目标的学生
拿到的却是同一份讲义、同一套题。单一问答式 AI 只能"答一题"，无法完成
**"画像 → 规划 → 多模态产出 → 答疑"**的闭环。

本作品用**多智能体融合**解决：不是让一个模型包办一切，而是 8 个分工明确的 Agent
各司其职、协同编排，围绕学生**个体画像**生成**个性化、多模态**的学习资源。

## 三、技术方案

### 3.1 多智能体架构（8 个协同 Agent）

| Agent | 职责 |
| --- | --- |
| Router | 意图识别，路由到正确 Agent |
| Profile | 对话式构建 8 维度学生画像 |
| Planner | 复合任务分解，规划资源组合 |
| Doc | 基于 RAG 生成个性化讲义 |
| Quiz | 生成多类型练习题 |
| Code | 生成可运行 Python 实操案例 |
| Media | 生成思维导图 / PPT / 动画脚本 |
| Tutor | 即时答疑 + 苏格拉底式引导 |

**编排规则**：Router 先行 → Profile 串行优先（其余依赖画像）→ Doc/Quiz/Code/Media 并行生成。

### 3.2 知识中枢（防幻觉）

- 知识库：内置《计算机网络》全课程结构化知识库（约 160 篇 Markdown，导入为 remio notes）。
- 检索：向量 + BM25 混合召回 + 规则 Rerank。
- 防幻觉三道防线：① `rag` 只依据知识库回答；② 生成强制 `[来源：章节>小节]` 引用；
  ③ 输出前过滤无来源断言。

### 3.3 在 remio 上的落地形态

每个 Agent = 一个**语义端点**，用 remio 能力实现（`run_prompt` / `rag` / `rag_stream` /
`search_notes` / `read_note` / `send_chat_message`），结构化结果用 UI 组件承载
（`card` / `list` / `choice` / `input` / `button` / `image`），自动化用 `POST /_event`
订阅实现。详见 `../aapp/eduagent-aapp-spec.md`。

### 3.4 跨产品能力（MCP）

同一引擎封装为 MCP 工具集（`backend/app/mcp_server.py`，12 个工具，零新增依赖），
可在 remio 及其他支持 MCP 的智能体宿主中注册调用。

## 四、创新点

1. **多智能体融合 + 个性化画像**：行业里"多 Agent"常止步于 demo，本作品把画像贯穿到
   每个生成端点，做到资源真正因人而异。
2. **知识锚定防幻觉落地**：RAG 检索 + 来源引用在 remio 能力原语上的 1:1 映射。
3. **双形态交付**：remio 原生 aApp 与 MCP 工具集共用同一引擎，跨产品可运行。
