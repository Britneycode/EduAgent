## 二、要解决的问题（赛道核心命题回应）

高校课程学习中，"千人一面"是核心痛点：同一个知识点，不同基础、不同目标的学生
拿到的却是同一份讲义、同一套题。单一问答式 AI 只能"答一题"，无法完成
**"画像 → 规划 → 多模态产出 → 答疑"**的闭环。

本作品用**多智能体融合**解决：不是让一个模型包办一切，而是 10 个分工明确的 Agent
各司其职、协同编排，围绕学生**个体画像**生成**个性化、多模态**的学习资源。

## 三、技术方案

### 3.1 多智能体架构（10 个协同 Agent）

| Agent | 职责 | remio 端点 |
| --- | --- | --- |
| Router | 意图识别，路由到正确 Agent | `route_intent`（E1） |
| Profile | 对话式构建 8 维度学生画像 | `build_profile`（E2） |
| Planner | 复合任务分解，规划资源组合 | `plan_learning`（E3） |
| Doc | 基于 RAG 生成个性化讲义 | `generate_document`（E4） |
| Quiz | 生成多类型练习题 | `generate_quiz`（E5） |
| Code | 生成可运行 Python 实操案例 | `generate_code`（E6） |
| Media | 生成思维导图 / PPT / 动画脚本 | `generate_mindmap`（E7）/ `generate_ppt`（E8）/ `generate_animation`（可选） |
| Reading | 拓展阅读推荐（联网优先） | `generate_reading`（E9） |
| Tutor | 苏格拉底式答疑（知识库→网络两级） | `tutor_answer`（E10） |
| Video | 教学视频搜索（联网搜 B 站，可选） | `search_video`（可选） |

**编排规则**：Router 先行 → Profile 串行优先（其余依赖画像）→ Doc/Quiz/Code/Media 并行生成。

### 3.2 知识中枢（防幻觉）

- 知识库：LLM Wiki 知识中枢（`backend/app/wiki/`），内置三门自建课程——
  人工智能导论（13 章）、计算机网络（约 160 篇全栈资源）、算法设计与分析
  （10 章 + 习题/代码/实验/媒体全套配套），自动发现与切换。
- 检索：向量（bge-small-zh 中文向量）+ BM25 混合召回 + 规则 Rerank。
- 防幻觉三道防线：① 生成只依据检索片段、不足则标注；② 强制 `[来源：章节>小节]`
  引用；③ 输出前过滤无来源断言（`content_guard`）。
- remio 侧落法：锚定型端点用 `run_prompt(capabilities="none")` **物理禁止联网**，
  由 `search_notes` + `read_note` 注入知识库**正文**；E10 答疑以首行 `GROUNDED` /
  `INSUFFICIENT` 显式上报覆盖度，升级联网必须显式发生，来源按
  `📚 课程知识库` / `🌐 网络` 分级标注。

### 3.3 在 remio 上的落地形态

每个 Agent = 一个**语义端点**（共 10 个，E1–E10），用 remio 能力实现
（`run_prompt` / `search_notes` / `read_note` / `rag` / `rag_stream` /
`web_search` / `web_get` / `send_chat_message`），结构化结果用 UI 组件承载
（`card` / `list` / `choice` / `input` / `button` / `image`），自动化用
`POST /_event` 订阅实现。详见 `../aapp/eduagent-aapp-spec.md`。

### 3.4 跨产品能力（MCP）

同一引擎封装为 MCP 工具集（`backend/app/mcp_server.py`，**12 个工具**，stdio
JSON-RPC，零三方依赖）：`route_intent` / `search_knowledge` / `extract_profile` /
`generate_document` / `generate_quiz` / `generate_code` / `generate_mindmap` /
`generate_ppt` / `generate_reading` / `generate_animation` / `tutor_answer` /
`list_courses`。可在 remio 及其他支持 MCP 的智能体宿主中注册调用，
见 `../mcp/README.md`。

## 四、创新点

1. **多智能体融合 + 个性化画像**：行业里"多 Agent"常止步于 demo，本作品把画像贯穿到
   每个生成端点，做到资源真正因人而异。
2. **多课程知识中枢**：不止一门课的 demo，三门自建课程知识库 + 混合检索，可扩展为
   课程平台。
3. **知识锚定防幻觉落地**：三道防线在 remio 能力原语上的 1:1 映射（含平台 `rag`
   对 File 笔记失效时 `search_notes → read_note` 的兜底链路）。
4. **双形态交付**：remio 原生 aApp 与 MCP 工具集共用同一引擎，跨产品可运行。

## 六、风险与边界

- remio aApp 打包/上架在 aapp-studio 客户端内完成，需 remio 账号（外部依赖）。
- 联网能力（`web_search`）依赖用户配置商业搜索源且可能额度耗尽，所有 web 调用
  均 try/except 降级到知识库作答并提示，不静默失败。
- 本方案提供了可执行规格与自验证 MCP 工具集，规避了对封闭 SDK 的硬依赖。
