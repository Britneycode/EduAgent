## 二、RAG 检索质量评测（真实知识库，含双模式双口径）

用真实课程知识库（计算机网络 CN101）做端到端检索评测，24 条学生式查询（覆盖 cn01~cn07
七个授课章节，每章 2~4 条）。经下方「检索质量修复」后，有效 chunk 由 816 收敛到 419 个
（清掉 48.6% 的非知识内容）。

鉴于知识库存在「授课讲解 vs 习题 cn09 vs 事实卡 cn99」的内容重叠，单一「章节命中」口径
无法真实反映检索效果，本报告并陈两个口径：

- **口径 A · 授课章节命中（严格）**：top-k 是否命中预期授课章节（cn01~cn07）。
- **口径 B · 内容相关命中（宽松）**：top-k 是否有 chunk 标题/正文包含该查询的核心知识点
  关键词。更贴近产品目标——E4 生成把 top-k 注入 prompt，检索到相关知识即可支撑生成，
  不纠结落在哪个章节。

| 模式 | 口径A 章节 top-1 | 口径A 章节 top-3 | 口径B 内容 top-1 | 口径B 内容 top-3 |
| --- | --- | --- | --- | --- |
| 纯 BM25 词法（下限） | 41.7% | 66.7% | 83.3% | 91.7% |
| **BGE + BM25 混合（生产）** | **41.7%** | **75.0%** | **100%** | **100%** |

**结论**：

1. **内容相关命中率达到 100%**（BGE top-1 与 top-3 均为 24/24）：检索系统对全部 24 条
   学生查询都能在 top-1 找到能回答该问题的知识内容，这是「知识中枢」有效性的最直接证据；
2. **向量检索增益确定**：BGE 相对纯 BM25，内容相关 top-1 提升 +16.7pp（83.3%→100%），
   章节命中 top-3 提升 +8.3pp（66.7%→75.0%），证明混合检索对词法检索有确定性增益；
3. **章节命中 75% 是知识组织问题而非检索失败**：剩余未命中章节的查询，其 top 结果全是
   内容正确的习题/事实卡（内容相关性口径已 100%），只是落点不是授课章节本体。

复现：
```bash
cd backend
uv run python tests/evals/eval_rag_hit_real.py          # 双模式对比（首次加载 BGE 约 9s，离线可用）
uv run python tests/evals/eval_rag_hit_real.py dev      # 仅词法下限（快）
uv run python tests/evals/eval_rag_hit_real.py bge      # 仅真实混合
```

### 检索质量修复（评审发现并已落地）

评审定位到四类问题，全部在 `backend/app/wiki/ingestion.py`（frontmatter 解析、过滤）与
`rag_engine.py`（排序加权）落地，并有回归测试保护：

1. **元内容 chunk 污染（已修）**：知识文档内嵌「导师 Agent 教学提示」「学习目标」「生成
   钩子」等给 Agent 的 prompt 元文本，被切成独立 chunk 进入检索。修复：新增
   `_META_SECTION_KEYWORDS` 标题黑名单，解析后统一过滤；
2. **课程组织材料混入检索（已修）**：课程总纲（课程简介/学习路径/知识地图/术语表/索引）
   与治理文档（图谱/质量检查）是「关于知识库的知识」而非学科知识。修复：解析 frontmatter
   的 `doc_type`，`governance`/`syllabus`/`glossary` 等一律不入检索；
3. **习题/实验/代码抢占授课讲解（已修）**：学生问概念时，题面与题目解析因词面同构抢占
   讲课正文。修复：`rag_engine` 按 `doc_type` 加权排序，`knowledge`/`fact_card` 优先，
   `exercise_set`/`lab`/`code_case`/`media_resource` 降权；
4. **授课讲解检索信号弱（已修）**：授课 chunk 标题是通用词（「知识讲解」），正文长而被
   向量稀释。修复：把 frontmatter 的 `rag.embedding_hints` 注入检索文档，对齐作者设计意图；
   并补物理层缺失的「传输介质」「编码与调制」两篇讲解文档（原 cn02 仅一篇概述，是
   「双绞线光纤」「调制解调」查询真正落空的主因）。

回归测试：`test_knowledge_ingestion_filters_meta_sections`、
`test_knowledge_ingestion_filters_non_retrievable_doc_types`；引擎全量 142/142 通过。

## 四、防幻觉机制的结构性保证（非抽样评测，而是架构强制）

EduAgent 的防幻觉不依赖模型自觉，由三层工程强制：

1. **物理禁网生成**：remio aApp 全部生成/答疑端点（E4–E10）调用
   `run_prompt(capabilities="none")`，模型侧无联网工具可用，知识上下文只能由代码注入；
2. **三级来源显式判定**：课程知识库（📚）→ 会话材料（📎）→ 网络（🌐），
   覆盖层级由代码按各层检索命中判定（不由模型自报），切换必须显式标注，禁止静默；
3. **引用白名单**：联网内容只引用代码实际 `web_get` 抓取成功的 URL；
   引擎侧另有 `content_guard` 输出过滤（虚构引用/低置信度暴露警告，见安全基线）。

## 六、运行环境说明

- Python 3.12 / uv 管理依赖；测试默认 SQLite + 本地向量库，零外部服务可跑通。
- BGE 向量检索离线可用（本地 HuggingFace 缓存 `BAAI/bge-small-zh-v1.5`）；
  脚本内置 `HF_HUB_OFFLINE=1` 强制离线加载，避免无网环境卡在 Hub 检查。
- 评测中发现的唯一环境干扰：沙箱化 CI 若拦截子进程管道，会造成
  `test_code_sandbox` 等 8 例假失败；非沙箱环境 140/140 全绿，
  已在仓库复现确认，非代码缺陷。
