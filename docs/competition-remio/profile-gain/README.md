## 修订后的实验协议

- 范围：后端 `DocAgent.build_prompt` 的画像消融；不是 remio aApp 端到端测评，不测试画像抽取或检索质量。
- 样本：TCP三次握手、子网划分、DNS解析三个主题 × 基础补齐、考试强化、工程实践三类合成画像，共9对、18份讲义。每对独立生成一份无画像基线，不复用基线。
- 唯一实验变量：画像字段是否提供；主题、知识正文、实际DocAgent提示词结构、模型和篇幅要求保持一致。固定课程正文而不重复检索，避免把检索波动混入画像效果。
- 每对生成顺序由固定种子打乱；裁判不告知生成条件，仅显示A/B讲义，交换顺序再次评分。属于匿名换序模型评审，**不是人工双盲试验**。
- 使用已配置的两个不同模型；禁止开发模拟与静默模型回退。每个新运行先做连接预检，最多38次调用（2次预检+18次生成+18次评分）。温度0.7，单次输出上限4096 tokens；实际金额取决于供应商价格。
- 每份讲义按难度匹配、示例贴合、表达适配、目标可执行性、事实准确性分别给1至5分，保留原始评分、引文及理由。
- 主指标：前四维在两次换序评分后取平均，再计算每对“有画像减无画像”，最后对有效样本取均值；另外报告正增益/平局/负增益样本数及事实准确性差值。
- 所有失败保留，不选择性删掉负结果；有效样本少于9对时必须明确完成率，不能按完整实验宣传。检查A/B换序的差异，不能把18次评分当成18个独立样本。
- 原始提示词、正文、输出、裁判原文、分数、知识文件哈希、脚本哈希、Git版本与模型名称均落盘。模型服务本身的随机性意味着重跑不保证字节一致。
