# EduAgent 需求分析说明书

更新时间：2026-06-12

## 1. 文档目的

本文档说明 EduAgent 的需求来源、目标用户、学习痛点、典型场景、功能需求、非功能需求，以及前沿 AI 技术与学习需求之间的结合点。文档重点回应比赛要求中的“深入了解和研究新时代大学生学习需求”与“明确技术与需求结合点”。

## 2. 需求研究方法与边界

本项目当前采用“赛题文本分析 + 案头研究 + 工程原型验证 + 可回填调研模板”的方式进行需求分析。

| 来源 | 用途 | 边界说明 |
|---|---|---|
| 赛题要求 | 明确多智能体、画像、资源生成、路径规划、智能辅导、学习效果评估等核心任务 | 作为刚性要求，不替代用户调研 |
| 案头研究 | 抽取高等教育数字化、AI 素养、智能辅导和 AI+教育趋势 | 只作为背景依据，不写成项目自有问卷结论 |
| 项目原型 | 通过演示脚本和样例数据验证学习闭环是否可运行 | 样例数据用于演示，不代表真实用户统计 |
| 后续问卷与访谈模板 | 供团队在提交前或赛后继续回收数据 | 本文档不虚构样本量和百分比 |

公开资料参考：

- 国家发展改革委、国家数据局等发布的[《人工智能+教育》行动计划](https://www.nda.gov.cn/sjj/zwgk/zcfb/0413/20260410162428109058250_pc.html)提出推动人工智能赋能教育教学、学习方式和治理方式变革。
- UNESCO 发布的 [AI Competency Framework for Students](https://www.unesco.org/en/articles/ai-competency-framework-students)强调学生需要具备理解、使用和反思 AI 的能力。
- 艾瑞咨询发布的[《2024 年人工智能+教育行业发展研究报告》](https://pdf.dfcfw.com/pdf/H3_AP202408051639144645_1.pdf?1723644716000.pdf=)反映 AI 与教育场景融合正在从工具使用走向流程重构。
- 《生成式人工智能增强智能辅导系统研究》可作为智能辅导系统设计的参考资料：[PDF 链接](https://openedu.sou.edu.cn/upload/qikanfile/202403291857378241.pdf)。

## 3. 背景与问题定义

高等教育正在从标准化教学向个性化、自主化、智能化学习支持转型。大学生在课程学习、专业能力提升、考试复习、科研入门和就业准备中面临的主要矛盾，不是单纯“缺少资源”，而是“资源、目标、基础和反馈之间缺少稳定匹配机制”。

EduAgent 将问题定义为：

1. 学生资源获取成本高：资料分散在课件、教材、视频、笔记、搜索引擎和问答平台中，难以形成结构化学习路径。
2. 个体差异难以被持续理解：学生基础、认知风格、学习节奏、目标和薄弱点不同，传统问答工具通常只响应当前问题。
3. 学习资源缺少闭环：讲义、题目、代码、PPT、视频等材料常被孤立生成，难以与测验结果、错题复习和后续路径联动。
4. AI 生成内容可信度不足：学生需要知道内容来自哪里、是否命中课程知识、是否存在低置信或安全风险。
5. 学习过程缺少可观测视角：学生需要知道 Agent 正在做什么、资源生成进度如何、测验反馈怎样影响后续路径。

## 4. 目标用户

| 用户 | 主要目标 | 关键需求 |
|---|---|---|
| 本科生 | 快速理解课程知识、完成复习和练习 | 个性化讲解、多模态资源、错题复习、路径规划 |
| 研究生或科研入门学生 | 了解专业知识脉络，形成专题学习材料 | 可信来源、拓展阅读、代码案例、知识图谱 |
| 参赛评审 | 判断系统是否满足多智能体、个性化、多模态和可运行要求 | 清晰文档、演示链路、测试证据、图表和合规说明 |

## 5. 用户画像与典型用户故事

### 5.1 学生画像维度

EduAgent 当前采用 8 维动态学习画像：

| 维度 | 说明 | 对系统的影响 |
|---|---|---|
| 知识基础 | 对课程模块的掌握程度 | 决定讲解深度和先修知识提示 |
| 认知风格 | 图文、读写、动手、听觉等偏好 | 决定资源形态和示例方式 |
| 学习目标 | 考试、科研、竞赛、就业等 | 决定资源重点和路径节奏 |
| 易错点/薄弱点 | 从对话和测验中提取 | 决定错题复习和强化练习 |
| 学习节奏 | 快速、适中、深入 | 决定内容拆分粒度 |
| 兴趣方向 | 偏好的专业子领域 | 决定拓展阅读和案例选择 |
| 编程能力 | 对代码案例和实践项目的适配度 | 决定代码难度和注释密度 |
| 时间投入 | 每周可学习时间 | 决定学习路径周期和任务量 |

### 5.2 典型用户故事

| 编号 | 用户故事 | 验收口径 |
|---|---|---|
| US-01 | 作为一名机器学习基础一般的学生，我希望用自然语言告诉系统自己的基础和目标，系统能生成画像 | 画像页显示专业、年级、基础、认知风格、每周学时和薄弱点 |
| US-02 | 作为一名复习反向传播的学生，我希望一次获得讲义、题目、代码、导图和 PPT | 聊天页出现多 Agent 状态和多类型资源卡 |
| US-03 | 作为一名担心 AI 幻觉的学生，我希望看到生成内容的来源和置信提示 | 资源卡展示来源、相关度、来源片段和低置信提示 |
| US-04 | 作为一名需要自测的学生，我希望答题后错题能进入复习队列 | 客观题答错后，复习页和仪表盘显示待复习项 |
| US-05 | 作为一名学生，我希望看到 Agent 处理进度和学习反馈如何影响后续推荐 | 学习分析页展示 Agent 可观测、测验反馈、错题复习和路径进度 |

## 6. 样例场景支撑

仓库内置演示场景位于 `backend/knowledge/ai_intro/demo_scenario.json`，用于稳定跑通“注册登录 -> 画像确认 -> 资源 -> 测验 -> 路径 -> 评估仪表盘 -> Wiki -> 资源中心”的闭环。

核心样例：

- 课程：人工智能导论
- 主题：反向传播算法
- 用户输入：计算机专业大三学生，机器学习基础一般，链式法则薄弱，每周约 6 小时，偏好图文结合
- 生成请求：围绕反向传播生成讲义、练习题、代码例子、思维导图和 PPT
- 验收检查：画像候选确认、Agent 状态流、多资源生成、错题复习、学习路径、RAG 来源命中、资源中心沉淀

该场景是系统功能验证和答辩演示样例，不作为真实用户统计结论。

## 8. AI 技术与需求结合点

| 学习需求 | AI 技术 | EduAgent 实现方法 |
|---|---|---|
| 理解学生差异 | LLM 结构化抽取 + 规则兜底 | Profile Agent 从自然语言和学习行为中更新画像 |
| 生成多类型资源 | 多 Agent 分工 + LLM 生成 | Doc、Quiz、Code、Media、Video、Tutor 分别处理不同资源 |
| 降低幻觉风险 | RAG + 知识图谱 + 来源引用 | 生成前检索课程知识，生成后展示来源片段和置信度 |
| 提升等待体验 | SSE 流式输出 + Agent 状态 | 聊天页展示阶段状态和资源生成进度 |
| 支持学习闭环 | 测验反馈 + 错题复习 + 路径推进 | 答题结果进入画像、复习队列、学习路径和仪表盘 |
| 支持多模态表达 | Mermaid/PPTX/动画包/TTS | 前端展示导图、PPT、动画分镜，TTS 可朗读资源 |
| 支持学习过程解释 | 数据聚合 + 可观测面板 | 学习分析页展示状态、耗时、薄弱点和下一步建议 |

## 9. 非功能需求

| 编号 | 需求 | 说明 | 当前措施 |
|---|---|---|---|
| NFR-01 | 可运行性 | 常规开发环境可启动前后端 | README 和部署文档提供步骤 |
| NFR-02 | 响应体验 | 避免长时间白屏 | SSE、Agent 状态、并行资源生成 |
| NFR-03 | 可观测性 | 能查看 Agent 链路和错误 | `agent_run_events` 与分析页面板 |
| NFR-04 | 内容安全 | 输入输出需经过规则或外部审核 | 本地规则 + 可选讯飞安全护栏 |
| NFR-05 | 可追溯性 | 生成内容可显示来源 | sources、confidence、来源片段 |
| NFR-06 | 可维护性 | 前后端分层，文档和测试可复用 | FastAPI、Next.js、测试基线、文档包 |
| NFR-07 | 合规性 | 标注开源项目和 AI 工具 | `OPEN_SOURCE_LICENSES.md` 和合规说明 |

## 10. 调研数据回填模板

以下模板用于团队在实际发放问卷或访谈后补充真实数据。当前文档不填入虚构样本量。

### 10.1 问卷回收摘要

| 项目 | 待填写 |
|---|---|
| 调研时间 | 待填写 |
| 调研对象 | 待填写，例如计算机类/电子信息类/通识课学生 |
| 样本量 | 待填写 |
| 年级分布 | 待填写 |
| 专业分布 | 待填写 |
| 主要学习痛点 Top 5 | 待填写 |
| 最希望 AI 提供的能力 Top 5 | 待填写 |
| 对内容可信引用的关注度 | 待填写 |
| 对多模态资源的偏好 | 待填写 |

### 10.2 问卷题目建议

1. 你当前最常见的课程学习困难是什么？
2. 你是否经常需要在多个平台之间寻找学习资料？
3. 你更偏好的学习资源形式是什么？可多选：文字讲义、图解、视频、题目、代码案例、PPT、思维导图。
4. 你是否希望 AI 根据你的基础和目标自动调整讲解深度？
5. 你是否关注 AI 生成内容是否有来源和可信依据？
6. 你是否希望练习结果自动影响后续学习计划？
7. 你是否愿意让系统记录学习行为以优化推荐？
8. 你希望系统记录哪些学习数据来优化后续推荐？

### 10.3 访谈提纲建议

1. 请描述最近一次为某门课寻找资料的过程。
2. 你遇到不理解的知识点时，通常如何求助？
3. 你使用通用 AI 工具学习时，最满意和最不满意的地方是什么？
4. 你怎样判断一份 AI 生成学习材料是否可信？
5. 如果系统可以生成一整套学习资源，你最希望它先生成什么？
6. 你希望系统如何提醒你复习错题或薄弱知识点？
7. 你愿意让系统长期保留哪些学习数据，哪些希望随时清除？

## 11. 需求验收标准

| 验收项 | 验收方法 | 通过标准 |
|---|---|---|
| 画像构建 | 输入演示画像提示词 | 画像页显示至少 6 个有效维度 |
| 多 Agent 协同 | 输入复合资源生成请求 | 聊天页出现 Router/Profile/Planner/Doc/Quiz/Code/Media/Tutor 等状态或结果 |
| 多资源输出 | 检查资源卡 | 至少出现 5 类资源或其可用提示 |
| 学习闭环 | 完成测验并故意答错 | 错题进入复习队列，仪表盘显示学习反馈 |
| 可信引用 | 检查资源卡来源区域 | 显示来源、相关度、片段或低置信提示 |
| 课程隔离 | 切换人工智能导论/计算机网络 | Wiki 检索和路径节点按课程展示 |
