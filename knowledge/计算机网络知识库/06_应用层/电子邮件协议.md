# 电子邮件协议

## 1. 学习目标
- 理解电子邮件系统的组成（用户代理、邮件服务器、邮件协议）。
- 掌握 SMTP 的发送流程与工作原理。
- 区分 POP3 与 IMAP 在邮件收取方式上的差异。
- 了解 MIME 在传输多媒体邮件中的作用。

## 2. 核心概念
电子邮件通过 SMTP 在邮件服务器之间推送邮件，用户通过 POP3 或 IMAP 从自己的邮箱服务器拉取邮件。

## 3. 知识讲解

### 3.1 系统组成
- **用户代理（UA）**：邮件客户端，如 Outlook、邮件 App。
- **邮件服务器**：发送/接收服务器，负责转发与存储。
- **协议分工**：发送用 SMTP，收取用 POP3/IMAP。

### 3.2 SMTP 发送流程
1. 发送方用户代理把邮件交给本地邮件服务器（SMTP 提交）。
2. 发送服务器通过 SMTP（25 端口）把邮件推送到接收方邮件服务器。
3. 接收方服务器把邮件存入收件人邮箱，等待收件人收取。

SMTP 是"推"协议，使用命令-响应交互：`HELO` → `MAIL FROM` → `RCPT TO` → `DATA` → 结束。

### 3.3 POP3 与 IMAP
- **POP3（110 端口）**：
  - "下载并（通常）删除"模型：邮件从服务器拉到本地后服务器端常被清除。
  - 适合单设备使用，离线可读。
- **IMAP（143 端口）**：
  - 邮件保留在服务器，客户端同步查看。
  - 支持多设备、文件夹管理、部分下载；是目前主流协议。
- 两者取信都基于 TCP，认证后操作邮箱。

### 3.4 安全增强
- SMTPS/提交端口 587（STARTTLS）、POP3S（995）、IMAPS（993）在明文协议上加 TLS 加密。
- 相比传统 25 端口明文 SMTP，现代部署普遍要求加密与认证。

### 3.5 MIME
- SMTP 早期只支持 7 位 ASCII 文本。
- MIME 扩展支持附件、图片、多语言与 Base64/Quoted-Printable 编码。

## 4. 关键事实
- SMTP 用于发送与服务器间转发，POP3/IMAP 用于收取。
- 邮件地址格式 `user@domain`，domain 决定目标邮件服务器（借助 DNS MX 记录定位）。
- IMAP 支持多设备同步，POP3 偏"下载到本地"模型。

## 5. 易混淆点
- SMTP 不负责把邮件"交给最终用户"，它只送到收件人的邮件服务器。
- 不要把发送协议（SMTP）与收取协议（POP3/IMAP）混为一谈。
- 邮件加密传输不等于邮件内容加密存储，两者是不同层面的安全措施。
